# Workflow Evolution

## Ownership

- Distribution-managed files are executable machinery and shared skill instructions. Upgrade them only through a CodeCraft Starter distribution or an explicitly reviewed local fork.
- Project-owned files include the working agreement, project configuration, plans, responsibility maps, review decisions, and protected-asset registry. The installer creates them but upgrades never overwrite them.

## Learning loop

1. Perform a new workflow task and save evidence under `automation/`.
2. Perform and document the second similar task independently.
3. On the third occurrence, compare the evidence, collaborate on an automation proposal, and assign Semantic Versioning beginning at `0.1.0`.
4. Test executable boundaries and machine-consumed contracts. Do not pin prose or human judgment with brittle tests.
5. Record contextual coaching as pending, obtain a human disposition, and keep that decision separate from implementation permission.

## Local changes and upgrades

Run the package doctor before and after a local workflow change. A managed-file divergence is deliberate fork evidence, not something an upgrade may overwrite. Promote broadly useful learning back to the distribution; keep domain-specific decisions in project-owned files.

When upgrading, inspect reported conflicts and merge them explicitly. Never use a force flag to replace local workflow decisions.
